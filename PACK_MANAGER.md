# PGR_Make 0.5 — Pack Manager

## Назначение и ограничения

Pack Manager хранит несколько версий инструментов одновременно, позволяет закрепить конкретные исполняемые файлы за проектом и устанавливать **проверенные ZIP-дистрибутивы** в `C:\PGR\Pack`. Он **не** является универсальным установщиком MSYS2/GCC/MSVC: пакеты с зависимостями нужно импортировать целиком либо зарегистрировать внешнюю установку. Он не скачивает инструменты без явного действия пользователя.

### Структура

```text
C:\PGR\
  PGR_Make.exe
  PGR_Make_GUI.exe
  tools\zip_guard.ps1
  Pack\
    catalog.json         # белый список проверенных дистрибутивов
    registry.json        # управляемые установки и контрольные суммы
    cmake\4.4.4-windows-x86_64\...
    ninja\1.13.1-windows-x86_64\ninja.exe
    Temp\                # временные распаковки
    Retired\             # удалённые из реестра наборы (карантин)
  Project\Calculator\config.cfg
```

Имена фактических папок сохраняются в нижнем регистре по полю `tool`. Для Windows в `Pack` следует **оставлять** DLL и вспомогательные файлы рядом с инструментами. PGR_Make не удаляет системные версии компиляторов.

## GTK4

- В настройках появился раздел **Pack Manager · версии и окружение сборки**. Его выпадающие списки закрепляют конкретные записи реестра за проектом.
- Кнопка **Открыть менеджер Pack** показывает установленные версии, результат проверки их запуска и пакеты из каталога.
- **Скачать и установить** скачивает архив по HTTPS, проверяет SHA-256, безопасно распаковывает и регистрирует пакет.
- **Из ZIP** импортирует локальную копию того же архивного пакета с тем же контрольным хешем.
- **Убрать из Pack** недоступно для версий, закреплённых за проектом/профилем. Файлы переносятся в `Pack\Retired`, а не удаляются.
- После установки нужно перезапустить GUI, чтобы обновить выпадающие списки.
- Журнал на вкладке сборки показывает ход операции. Долгая операция не блокирует GTK4 GUI.

## CLI

Из `C:\PGR`:

```bat
PGR_Make.exe --pack-catalog
PGR_Make.exe --pack-list
PGR_Make.exe --pack-install cmake@4.4.4@windows-x86_64
PGR_Make.exe --pack-import ninja@1.13.1@windows-x86_64 D:\Downloads\ninja-win.zip
PGR_Make.exe --project Calculator --pack-bind cmake cmake@4.4.4@windows-x86_64
PGR_Make.exe --project Calculator --pack-bind ninja ninja@1.13.1@windows-x86_64
PGR_Make.exe --project Calculator --ci
PGR_Make.exe --project Calculator --pack-unbind cmake
PGR_Make.exe --pack-retire cmake@4.4.4@windows-x86_64
```

### Импорт произвольного проверенного пакета

```bat
PGR_Make.exe --pack-import-custom gcc@11.4.0@windows-x86_64 ^
    D:\Downloads\gcc-11.4.0-full.zip ^
    <SHA256_ИЗ_НЕЗАВИСИМОГО_ДОВЕРЕННОГО_ИСТОЧНИКА> bin\g++.exe
```

ZIP должен содержать полный рабочий набор, включая компилятор C, C++, линкер и необходимые DLL. Обязательно проверьте его лицензию и источник. Укажите действительную SHA-256 сумму, **не** придуманный хеш. Указанная версия должна подтверждаться при `--version` запускаемого файла. `--pack-import-custom` также применим для LLVM/Clang, ARM/RISC-V toolchain, objcopy и т. д. Для MSVC предпочтительнее штатный установщик Microsoft и внешняя регистрация.

### Внешний инструментарий

```bat
PGR_Make.exe --pack-register gcc@14.2.0@windows-x86_64 ^
    C:\External\GCC\bin g++.exe
```

Это регистрирует существующую директорию без копирования файлов. При удалении записи внешние файлы остаются на месте.

## Независимые версии для разных проектов

Конфигурация проекта поддерживает новые поля:

```ini
compiler_id=gcc@11.4.0@windows-x86_64
cmake_id=cmake@4.4.4@windows-x86_64
ninja_id=ninja@1.13.1@windows-x86_64
objcopy_id=
```

Пустое поле означает старую логику поиска. **Непустое поле означает строгую привязку**: если версия отсутствует, недоступна, изменена или несовместима с платформой, сборка заканчивается ошибкой; подмены версией из системного PATH нет.

PGR_Make создаёт отдельный каталог `.pgr_build/<project>/environments/<hash>` для каждого набора закреплённых версий. Смена набора не перезаписывает предыдущий CMakeCache. Прямой режим по-прежнему пишет в настроенный `build/` и не обеспечивает инкрементальную сборку.

## Безопасность

1. Онлайн-скачивание только по HTTPS и по явно выбранной записи каталога; URL переадресации также ограничены HTTPS.
2. SHA-256 ZIP должен быть указан в доверенном каталоге или задан пользователем при импорте; архив с неверной суммой не распаковывается.
3. ZIP extractor отвергает абсолютные и выходящие за пределы временной папки пути, симлинки, дубликаты, превышения ограничений. Linux требует `python3`, Windows использует включённый PowerShell скрипт.
4. После распаковки проверяется заявленная версия исполняемого файла; затем сохраняется SHA-256 бинарника. При сборке закреплённая версия перепроверяется.
5. Стадия распаковки и окончательная установка находятся внутри `Pack` (операция перемещения на том же диске), пользовательские файлы не перезаписываются.
6. Удаление запрещено при привязке к активным **зарегистрированным проектам и профилям**. Проверка не охватывает проекты вне реестра, исполняемые процессы из сторонних приложений и одновременные действия независимых экземпляров GUI.
7. Никакая загрузка не происходит автоматически в CI.

**Граница доверия:** SHA-256 без удостоверенного источника сам по себе не доказывает подлинность дистрибутива. `catalog.json` является локальным списком доверенных URL/хешей, его необходимо защищать от несанкционированного изменения. Источники CMake и Ninja в поставляемом примере сверены с официальными публикациями и независимыми контрольными суммами. Перед добавлением новых версий обновите URL, платформу, SHA-256 и путь к исполняемому файлу.

## Что ещё требует проверки

Нативная компиляция GTK4 GUI и PowerShell ZIP-экстрактор на Windows (проверки здесь проведены на Linux). Отсутствует самостоятельная установка зависимостей MSYS2 GCC, MSVC, полный менеджер лицензий, цифровая подпись каталога и защита от одновременного изменения реестра несколькими процессами. Обновление Pack Manager не вносит намеренных изменений в проекты или установленные комплекты `Pack` при обычном запуске.


## Пакетная установка из GUI (0.8.1)

Кнопка «Скачать необходимые инструменты» выбирает последние проверенные версии GCC, Clang, CMake и Ninja, доступные в каталоге для текущей платформы. Один WinLibs ZIP содержит GCC и Clang. См. `PACK_BULK_INSTALL.md`. CLI-эквивалент: `--pack-install-all`.
