# Исправление сборки GTK4 GUI (26.10.2026)

## Причина

В старом `gui/main.cpp` обработчик кнопки выбора компилятора передавал
лямбду прямо в `G_CALLBACK(...)`. Внутри лямбды присутствовал шаблон
`std::pair<Gui*, std::string>`, содержащий запятую. Препроцессор C/C++ не
учитывает `<...>` при разделении аргументов макросов, поэтому компилятор
сообщал: `macro 'G_CALLBACK' passed 2 arguments, but takes just 1`.

## Изменения

- В `gui/main.cpp` введён `CompilerChoice` и отдельные C-совместимые
  обработчики `on_pack_compiler_clicked()` / `destroy_compiler_choice()`.
- Контекст обработчика теперь удаляется при освобождении GObject-сигнала.
- В `main.cpp` подавлены предупреждения о неиспользуемых `argc`/`argv`
  в Windows-ветке, где аргументы считываются через `CommandLineToArgvW`.
- Остальная логика CLI/TUI, CMake и регистрации проектов сохранена.

## Сборка в MSYS2 UCRT64

```bash
cmake -S . -B build-win -G Ninja \
  -DCMAKE_BUILD_TYPE=Release \
  -DPGR_STATIC_WINDOWS=ON \
  -DPGR_BUILD_GUI=ON \
  -DPGR_REQUIRE_GUI=ON
cmake --build build-win --parallel
```

Если старые объекты и CMakeCache приводят к непонятным ошибкам, удалите
**только ранее созданную папку** `build-win` своего исходного проекта,
после чего повторите конфигурацию.

## Проверка и ограничения

- CLI собирается на Linux (GCC 14.2), его автоматические тесты проходят.
- Отдельно проверено, что именованный обработчик корректно оборачивается
  макросом с той же структурой `G_CALLBACK`.
- Настоящая GTK4-сборка на Windows не выполнена в тестовой среде:
  здесь нет пакета `gtk4` для компиляции графического модуля.
- Предупреждения GTK4 `deprecated: Use GtkDropDown instead` и аналогичные
  относятся к старым API, но **не останавливают** сборку. Их миграция
  в более поздней версии GTK4 GUI потребует отдельного рефакторинга.
- `PGR_Make_GUI.exe` зависит от GTK4 DLL; линковка самого C++ runtime
  не превращает GTK4 в статическую библиотеку.
