# PGR_Make 0.7 — UX / GTK4

Версия основана на PGR_Make 0.6, сохраняет сборочное ядро, CLI/TUI, Pack Manager,
две темы и структуру установки `C:\PGR\`.

## Сценарий работы

1. Выбрать проект справа или нажать «Создать».
2. В верхней сводке проверить компилятор, закреплённую версию CMake, профиль и режим.
3. Выбрать режим: **Существующий CMake**, **PGR CMake** или **Прямая сборка**.
   Для существующего проекта с корневым `CMakeLists.txt` первый режим устанавливается по умолчанию.
   Выбор сохраняется в `Project/<имя>/.pgr_gui_mode`, отдельно от `config.cfg`.
4. Нажать «Проверить», чтобы увидеть недоступные пути и закреплённые инструменты.
   При отсутствии инструмента доступен переход в Pack Manager.
5. Нажать «Собрать»; вкладка **Результат** покажет итог. При ошибке откроется
   **Диагностика**, журнал остаётся доступен на соседней вкладке.
6. После успешной сборки можно открыть её каталог. **Запустить EXE** доступно
   только при наличии явно настроенного исполняемого файла, который был
   создан или изменён текущей сборкой. Для неизвестных и кросс-артефактов
   запуск не предлагается. Запуск всегда инициируется пользователем.

## Изменения GUI

- Полные команды TUI сохранены в «Дополнительные команды», но GUI больше не
  повторяет номера 1–38 в подписях.
- Конфигуратор по умолчанию показывает раздел «Основные»; остальные разделы
  доступны через категории и поиск.
- `GtkPaned` продолжает разделять настройки/проекты и нижнюю панель вывода;
  дополнительно сохраняются пропорции (тысячные доли). Старые абсолютные
  значения остаются читаемыми.
- Панель результатов: `Результат`, `Журнал`, `Диагностика`, `История`.
  История отображается строками по колонкам (время, статус, режим, длительность).
- Проверки подсвечивают поля с неверными путями. Полная проверка бинарных SHA
  выполняется по действию пользователя; поверхностная проверка — при открытии.
- При закрытии с изменённой конфигурацией показан диалог из трёх вариантов.
- Исходный дизайн Ash & Orange и компактные системные кнопки сохранены.

## Совместимость и миграция

`config.cfg`, `project.pgr`, `Pack/registry.json`, профильные файлы и
сгенерированные сборки **не меняются автоматически**. Новые предпочтения GUI
хранятся рядом с прежними, можно откатиться к версии 0.6. Старый файл
`.pgr_gui_layout` читается; новые записи `projects_permille` и
`output_permille` добавляются при сохранении.

Возможна одна запись `CMakeLists.txt` с дополнительными зависимостями GTK4,
которых нет в автоматическом CMake-генераторе. Для таких проектов нужно
использовать «Существующий CMake».

## Сборка Windows (MSYS2 UCRT64)

```cmd
cmake -S . -B build-win -G Ninja -DCMAKE_BUILD_TYPE=Release -DPGR_STATIC_WINDOWS=ON -DPGR_BUILD_GUI=ON -DPGR_REQUIRE_GUI=ON
cmake --build build-win --parallel
ctest --test-dir build-win --output-on-failure
```

GTK4 должен быть доступен в pkg-config. Для GUI нужны соответствующие DLL,
статически компонуется только runtime GCC. Без GTK4 `PGR_REQUIRE_GUI=ON`
выдаст явную ошибку конфигурации.

## Ограничения проверки

Проверка компиляции и тестов ядра выполнена на Linux/GCC 14.2. В текущем
окружении нет GTK4 SDK и Windows toolchain, поэтому нативная компиляция и
визуальная/GUI-автоматизация на Windows **не подтверждены**.
Статические проверки GTK не заменяют сборку с реальными заголовками GTK4.

Для приёмки на Windows проверить: пустой старт, выбор/создание проекта,
режим CMake по умолчанию, переключение режимов, сохранение/отмену при закрытии,
изменение размера окна и положения панелей, ошибки компиляции, установку из
Pack, поиск лога и обновление истории. Перед обновлением архивировать
`C:\PGR\Project`, `Pack` при установке не удалять.

## Диагностика и обновление 0.6 → 0.7

Сообщения компилятора группируются по файлам; записи `note` показываются
вложенными и сохраняют собственные файл и номер строки. После неуспешной
сборки GUI автоматически открывает диагностику с выделенной первой ошибкой.
Версия 0.7 добавляет `schema=7` в `.pgr_gui_layout` и переводит старую вкладку
журнала (`output_page=0`) в новый индекс `1`, не теряя выбор пользователя.

Значения версии в верхней сводке взяты из закреплённых идентификаторов Pack.
Если выбран `PATH`, сводка прямо отмечает, что версия **не закреплена**;
фактическая диагностика инструмента выводится в журнал при сборке. Это не
гарантирует воспроизводимость сборки без закрепления версии.
