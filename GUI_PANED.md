# PGR_Make GUI 0.2 — GtkPaned / полный конфигуратор

## Назначение

Новый интерфейс GTK4 разделён **горизонтальным `GtkPaned`**:

- **слева**: параметры и действия TUI, сгруппированные в раскрываемые секции. Внизу находятся вкладки «Журнал» и «Диагностика»;
- **справа**: список зарегистрированных проектов, создание и обновление списка, путь к выбранным исходникам.

Граница между панелями перетаскивается мышью. Для больших конфигураций слева есть вертикальная прокрутка.

Сохраняется текущая архитектура: GUI меняет `Project/<имя>/config.cfg`, а реальные команды выполняет отдельный `PGR_Make.exe`. CLI и TUI остаются доступны независимо.

### Новое поле package_dirs

`package_dirs` (многострочный список каталогов) сериализуется в `config.cfg` повторяющимися ключами. CMake получает `-DCMAKE_PREFIX_PATH=...`, а сгенерированный `CMakeLists.txt` содержит `list(PREPEND CMAKE_PREFIX_PATH ...)`. Это необходимо для поиска выбранных пользователем `*Config.cmake` без ручного редактирования CMake-файлов. Остальные ключи и формат конфигурации не изменены.

Выбор `FooConfig.cmake` определяет пакет `Foo`, добавляет его в `packages` и каталог файла в `package_dirs`. Цель импорта по умолчанию предполагается `Foo::Foo`. Если библиотека экспортирует другую цель, нужно исправить запись пакета вручную, например `Foo|Foo::SomeComponent`. Автоматическое определение экспортированных CMake-целей здесь не реализовано.

## Windows / MSYS2 UCRT64

Для этой версии необходим GTK **4.10 или новее**, поскольку используется `GtkFileDialog`. Установить зависимости:

```bash
pacman -S --needed mingw-w64-ucrt-x86_64-gtk4 mingw-w64-ucrt-x86_64-pkgconf mingw-w64-ucrt-x86_64-cmake mingw-w64-ucrt-x86_64-ninja mingw-w64-ucrt-x86_64-gcc
```

Затем в MSYS2 UCRT64 из каталога проекта:

```bash
cmake -S . -B build-win -G Ninja -DCMAKE_BUILD_TYPE=Release -DPGR_STATIC_WINDOWS=ON -DPGR_BUILD_GUI=ON -DPGR_REQUIRE_GUI=ON
cmake --build build-win --parallel
```

Полученные `PGR_Make.exe` и `PGR_Make_GUI.exe` должны располагаться рядом в `C:\PGR`. Компиляторы и CMake размещаются в `Pack`. Для GTK4 всё ещё нужны внешние runtime DLL, включая зависимые библиотеки GTK и данные в `share`; опция `PGR_STATIC_WINDOWS` делает статическими только runtime GCC/C++.

## Проверка

Запустить CLI-тесты (Python 3):

```bash
python tests/run_tests.py build-win/PGR_Make.exe
python tests/run_features.py build-win/PGR_Make.exe
python tests/run_gui_bridge.py build-win/PGR_Make.exe
python tests/run_gui_commands.py build-win/PGR_Make.exe
```

Протестировать GUI вручную: создать два проекта, переключить их в правой панели, поменять один или несколько флагов, сохранить настройки, заново открыть проект, выбрать путь с пробелами и кириллицей, собрать тестовое приложение и посмотреть вкладку «Диагностика». Перед очисткой проверить подтверждение.

**Ограничения:** в текущей среде GTK4 SDK отсутствует, поэтому проверка полноценной компиляции/запуска GUI на Windows должна быть проведена в MSYS2. Команда «Остановить» принудительно завершает CLI; дочерние процессы сборки могут потребовать отдельной остановки. Настройки, ещё не сохранённые, автоматически записываются при смене проекта, чтобы не терять их.
